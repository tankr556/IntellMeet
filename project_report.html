4. System Architecture & Real-Time Data Flow

IntellMeet utilizes an event-driven, decoupled micro-architecture where signaling, media streaming, and AI processing execute independently without blocking the core application event loop.

+---------------------------------------------------------------------------------------------------+ | CLIENT LAYER (React 19 + TypeScript + Vite) | | +-----------------------+ +------------------------+ +----------------------------------+ | | | Lobby / Dashboard | | WebRTC Video Room Dock | | Agile Kanban Board & Post-Meeting| | | +-----------------------+ +------------------------+ +----------------------------------+ | +-----------------------------------^------------------------------------^--------------------------+ | | [ Direct Media Mesh ] | [ HTTPS / REST API ] | [ WebSocket Signaling ] (Peer-to-Peer Audio/Vid)| (JWT / CRUD Data) | (Offers, Answers, ICE) v v +-----------------------+ +-----------------------------------------------+ | REMOTE PEER CLIENT |<=========================>| RENDER APPLICATION BACKEND | | (WebRTC Audio / Video)| | (Node.js + Express + TS) | +-----------------------+ | | | • Auth & User Management (JWT + bcrypt) | | • Meeting Orchestration & Signaling Server | | • AI Intelligence Service (Whisper & GPT-4o) | | • Prometheus Observability (/metrics) | +-----------------------+-----------------------+ | +-------------------------------+-----------------------+ | | | v v v +---------------------------+ +--------------------+ +--------------------+ | MONGODB ATLAS | | REDIS CACHE | | OPENAI API | | (Users, Meetings, Tasks) | | (Sessions, Pub/Sub)| | (Whisper, Summary) | +---------------------------+ +--------------------+ +--------------------+

Real-Time WebRTC Peer Connection Lifecycle

  1. Room Join: Client dispatches a join-room WebSocket event with room code and display name.
  2. SDP Offer / Answer: Existing peers receive user-joined and exchange Session Description Protocol (SDP) offers and answers through Socket.io.
  3. ICE Candidate Exchange: Network addresses and STUN candidate paths are routed in real-time, establishing a direct peer-to-peer DTLS/SRTP audio/video stream.
  4. Adaptive Layout: The client detects participant count and dynamically configures a 2-column downward-stacking grid with vertical scrollbars for 3+ members.
  5. Post-Meeting AI Hook: Upon call termination, recorded audio/transcripts trigger the AI pipeline to generate executive summaries and structured tasks.

6. Technical Highlights, Security & Problem Solving

Security & OWASP Mitigation

  • Stateless Authentication: Short-lived JWT access tokens stored in memory paired with HttpOnly, SameSite=Strict refresh cookies to prevent XSS and CSRF token exfiltration.
  • Password Security: High-entropy cryptographic hashing using bcrypt with 10 salt rounds.
  • Rate Limiting & DoS Protection: Configured express-rate-limit preventing brute-force attacks against authentication and room creation endpoints.
  • HTTP Hardening: Helmet.js headers enforcing strict Content Security Policy (CSP), anti-clickjacking X-Frame-Options, and HSTS.

Key Engineering Challenges & How They Were Solved

Challenge Root Cause Architectural Resolution
WebRTC Peer Desynchronization Race conditions when multiple clients joined simultaneously and exchanged SDP offers out-of-order. Implemented a deterministic initiator pattern through Socket.io where only newly joined peers create offers, while existing peers respond with answers.
Mobile Video Control Distortion Variable button widths caused by long text labels ("Recording...", "Leave") causing dock wrapping on phone screens. Standardized all controls into uniform 44x44px touch squircles with centered vector icons and a dedicated Chat jump button.
Vercel Direct Route 404s Single Page Application (SPA) routing failed when users accessed direct meeting links like /room/xyz. Authored root and client vercel.json rewrite configurations redirecting all client routes to /index.html.
Large Video Tile Overflow Adding 3 or more participants pushed tiles horizontally off-screen on compact displays. Engineered a responsive 2-column downward-stacking grid with a vertical scrollbar for 3+ members and automatic centering for odd last tiles.
